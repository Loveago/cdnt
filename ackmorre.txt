 API INTEGRATION GUIDE · VERSION 2
ACKMORRE API v2
How to sell data bundles and AFA registrations from your own website or app: every endpoint with real requests and replies, webhooks, errors and safe retries.

BASE URL: https://console.ackmorre.com/api/v2
AUTHENTICATION: X-API-Key header
FORMAT: JSON in, JSON out
BULK ORDERS: Up to 100 per request
CURRENCY: GHS (cedis)
GUIDE DATE: October 2026

1 Getting started
Get your API key from API Access in your ACKMORRE dashboard (your account needs API access approved).
Send it in the X-API-Key header on every request. Requests and replies are JSON.

X-API-Key: YOUR_API_KEY
Content-Type: application/json

Every reply has the same shape. Check ok first; on errors use error.code. Keep meta.request_id — quote it when you contact support.

SUCCESS 200
{
  "ok": true,
  "data": { ... },
  "meta": {
    "request_id": "req_112b2ba07d1ab13af712",
    "api_version": "2"
  }
}

ERROR 402
{
  "ok": false,
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Not enough balance for this order. Nothing was charged.",
    "required": 9,
    "available": 1
  },
  "meta": {
    "request_id": "req_02a0f778d7541a46bcff",
    "api_version": "2"
  }
}

Keep your key on your server only. Prices always come from your account — you never send a price. Your wallet is charged when an order is accepted. Optional: lock your key to your server IP under API Access -> Allowed IP addresses.

2 Endpoints at a glance
Base URL: https://console.ackmorre.com/api/v2
METHOD | PATH           | WHAT IT DOES
GET    | /me            | Account, balance and webhook status
GET    | /bundles       | Bundles and your prices
POST   | /orders        | Buy one bundle
POST   | /orders/bulk   | Buy up to 100 bundles
GET    | /orders        | List your orders
GET    | /orders/{ref}  | One order (our reference or yours)
POST   | /afa           | Submit an AFA registration
GET    | /afa           | List AFA registrations
GET    | /afa/{ref}     | One AFA registration

4 Place an order
POST /orders
Buy one bundle
FIELDS:
- bundle_id (integer, Required): An id from GET /bundles.
- recipient (string, Required): Ghana number, 10 digits, e.g. 0241234567.
- idempotency_key (string): Your unique ID for this order. Sending it again never charges twice.
- client_reference (string): Your own reference (up to 64 letters, numbers, _ -). Unique on your account.
- webhook_url (string): Send this order's status updates to this https:// address instead of your saved webhook URL.
- dry_run (boolean): true = check price and balance only. Nothing is charged.

curl -X POST "https://console.ackmorre.com/api/v2/orders" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"bundle_id": 1, "recipient": "0241234567", "client_reference": "INV-1001", "idempotency_key": "INV-1001", "webhook_url": "https://your-site.com/webhooks/ackmorre"}'

ERRORS:
422 VALIDATION_ERROR: A field is missing or wrong — error.fields says which.
404 BUNDLE_NOT_FOUND: Unknown bundle, or not available to your account.
403 NUMBER_BLACKLISTED: This number can't receive orders on that network.
403 NUMBER_NOT_VERIFIED: The network only accepts verified numbers right now.
409 DUPLICATE_ORDER: The number already has an order of the same size in progress.
409 CLIENT_REFERENCE_EXISTS: You already used this client_reference.
402 INSUFFICIENT_BALANCE: Top up your wallet. Nothing was charged.

5 Bulk orders
POST /orders/bulk
Up to 100 orders per request.
FIELDS:
- orders (array): Required. 1-100 items, each {"bundle_id", "recipient"} plus optional client_reference and webhook_url.
- idempotency_key (string): One key for the whole request.
- dry_run (boolean): Check every line and the total. Nothing is charged.

curl -X POST "https://console.ackmorre.com/api/v2/orders/bulk" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \

6 Check orders
GET /orders/{ref}
Use their reference (API_...) or your client_reference.
curl -X GET "https://console.ackmorre.com/api/v2/orders/INV-1001" \
  -H "X-API-Key: YOUR_API_KEY"

GET /orders
List orders with query parameters: status, recipient, client_reference, from, to, page, limit.

Note: Order status lookups (GET /orders, GET /orders/{ref}, GET /afa, GET /afa/{ref}) are disabled unless support enables them for your account. When disabled you get 403 STATUS_CHECKS_DISABLED. Use webhooks for results.

7 AFA registration
POST /afa
Submit a registration:
- full_name (string): Required. 3-150 characters.
- phone (string): Required. 10-digit Ghana number.
- ghana_card (string): Required. Format GHA-123456789-0.
- location (string): Required. Town or district.
- idempotency_key (string)
- client_reference (string)
- webhook_url (string)
- dry_run (boolean)

8 Webhooks
We send a POST with JSON to your webhook URL (or to the order's own webhook_url). Reply with any 2xx within 10 seconds.
Only final results are sent: delivered, failed, or refunded.
Results arrive together in one call (event orders.finished) with up to 100 results.
Headers:
- X-ACKMORRE-Signature: HMAC-SHA256 of the raw body with webhook secret (whsec_... on API Access page), hex.
- X-ACKMORRE-Event: Same as event, e.g. orders.finished
- X-ACKMORRE-Attempt: 1 for first try, 2 for retry

Order statuses:
- accepted: Paid, waiting to be sent.
- placed: Sent to the network provider.
- processing: Being delivered.
- delivered: Delivered. Final.
- failed: Not delivered — see the failure reason. Refunded by our team.
- refunded: Money returned to your wallet. Final.
- skipped: Data orders only: not sent (set by our team).
